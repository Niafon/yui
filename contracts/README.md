# Контракты

Межпроцессные сообщения (SRS 18.2). Каждое сообщение несёт
`protocol_version`, `message_id`, `timestamp`, `source` и `correlation_id`.

| Файл | Плоскость | Содержание |
|---|---|---|
| `common.proto` | обе | конверт, категории данных, чувствительность, риск, устройства |
| `control.proto` | control | сессии, состояние, разрешения, подтверждения, выражения аватара, ошибки |
| `data.proto` | data | аудио, транскрипты, дельты ответа, синтез, кадры камеры |
| `memory.proto` | — | кандидат в память, воспоминание, manifest вызова провайдера |
| `worker.proto` | — | контракт «ядро ↔ AI-воркер» |

## Состояние

MVP-транспорт — JSON с **теми же именами полей**: WebSocket между клиентами и
ядром, HTTP между ядром и воркерами. Схемы здесь — источник истины для имён и
семантики; кодогенерация включается, когда транспорт переводится на gRPC.

```bash
protoc --go_out=../core/gen --go_opt=paths=source_relative \
       --proto_path=proto proto/yui/v1/*.proto
```

## Правила изменения

- Номера полей не переиспользуются никогда.
- Новая категория данных — это изменение контракта, а не строка в конфиге:
  ничто не должно передаваться без категории.
- Несовместимая версия протокола → понятная ошибка клиенту, а не молчаливая
  деградация (NFR-004).
