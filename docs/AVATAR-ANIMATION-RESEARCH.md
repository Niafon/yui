# Idle-анимации и эмоциональные реакции

Исследование от 21 сентября 2026; интеграция выполнена 22 сентября 2026.
В VRM подключены девять VRMA-клипов, в Live2D — эмоции и штатные motions.
Атрибуция и контрольные суммы находятся в `desktop/public/assets/animations`.

## Подходящие готовые решения

| Решение | Что использовать в Yui |
| --- | --- |
| [pixi-live2d-display](https://guansss.github.io/pixi-live2d-display/motions_expressions/) | Уже установлен. Автоматически выбирает idle-движения из группы `Idle` у Cubism 4. `model.motion(group, index)` запускает жест; приоритет NORMAL прерывает idle. Выражения лица задаются отдельно. |
| [Официальный three-vrm-animation](https://github.com/pixiv/three-vrm/tree/dev/packages/three-vrm-animation) | Модуль для VRM Animation (.vrma) в экосистеме уже установленного three-vrm. Подключить загрузку клипов и проигрывание через Three.js AnimationMixer. Версию согласовать с three-vrm. |
| [Hanami](https://github.com/Undi95/Hanami) | Готовый пример компаньона: циклический idle, однократный жест эмоции, talking idle, дыхание и покачивание поверх клипа. Эмоции приходят тегами из LLM. Файлы называются `idle`, `happy`, `sad` и т. п.; суффиксы дают варианты жестов. Полезен как образец механики. |

Перед переносом конкретных клипов из Hanami сверить их отдельные лицензии и
атрибуцию в [NOTICE](https://github.com/Undi95/Hanami/blob/main/NOTICE.md).
Код приложения и анимационные ассеты могут иметь разные условия использования.

## Что уже есть в Yui

- Live2D обновляет модель, управляет мимикой и губами. Библиотечный idle доступен,
  если он включён в пакет модели. Соответствие эмоции и жеста ещё не задано.
- VRM проигрывает idle, talking idle и однократные эмоции через AnimationMixer.
  Мимика и губы обновляются отдельно.
- Ядро просит модель поставить в начале ответа ограниченный тег эмоции,
  удаляет его из текста и озвучки даже при разделении между сетевыми чанками
  и сразу отправляет событие реакции. При отсутствии тега действует прежняя
  локальная оценка эмоционального состояния.

## Реализованная механика

Длительное настроение остаётся в ядре. Для реплики LLM выбирает один тег
`[emotion:...]` из ограниченного набора. Ядро удаляет тег из текста и TTS,
включая случай разделения тега между сетевыми чанками. Неизвестный тег не
запускает специальную реакцию. При отсутствии тега действует прежняя оценка
настроения по тексту пользователя. Жест для VRM выбирается по карте имён,
а Live2D использует имеющуюся группу TapBody и отдельную мимику.

| Эмоция | Мимика | Жест |
| --- | --- | --- |
| joy / warm | улыбка | кивок, раскрытая ладонь |
| concern / sad | обеспокоенность | небольшой наклон головы, спокойная поза |
| alert / surprise | удивление | короткое отклонение назад |
| neutral / think | нейтральная / задумчивая | взгляд в сторону, лёгкий наклон |

Это установленное соответствие для встроенных моделей; для новых пакетов
Live2D имена групп и файлов могут отличаться.

Состояния: idle → listening → thinking → speaking → idle. VRM плавно переходит
от idle к жесту и обратно, а разговорный idle включается при речи. Мимика и
губы обновляются отдельно от тела. Live2D использует штатные приоритеты и fade;
звук в motion-файлах отключён, чтобы не перекрывать TTS.

При смене модели асинхронные загрузки старой модели игнорируются; отсутствие
одного клипа оставляет остальные рабочими. Для пользователей с reduced-motion
движения VRM и жесты Live2D отключаются.

Рекомендация: для Live2D использовать существующий motion manager; для VRM —
официальный VRMA-модуль и несколько лицензированных клипов. Механику Hanami
использовать как ориентир для очереди жестов и разделения лица, тела и губ.
